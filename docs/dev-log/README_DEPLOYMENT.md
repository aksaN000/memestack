# MemeStack — Deployment Runbook

Deploys both frontend (CRA) and backend (Express) to Vercel from a single
monorepo. This doc is the end-to-end setup for a fresh environment plus the
playbook for redeploying after changes.

---

## Repo layout

```
memestack/
  backend/          Express 5 + Mongoose 8 + JWT + Cloudinary
    api/            Vercel serverless entry (api/index.js)
    src/
    vercel.json
  frontend/         React 19 + MUI 7 + react-router-dom v7
    src/
    build/          Generated by `npm run build`
    vercel.json
  UPGRADE_NOTES.md  Redesign + feature change log
  README_DEPLOYMENT.md (this file)
```

Live demo: <https://470-project-25ao.vercel.app/>
Source: <https://github.com/aksaN000/470_project>

## Prerequisites

- Node 18+ and npm 9+
- A MongoDB Atlas cluster (free tier is fine)
- A Cloudinary account (for image upload)
- A Vercel account connected to the GitHub repo
- A JWT secret (any long random string)

## Environment variables

Set these on Vercel under each project's **Settings → Environment Variables**.
Do NOT commit `.env` files — they're gitignored.

### Backend (`memestack/backend`)

| Key                     | Example                                           |
| ----------------------- | ------------------------------------------------- |
| `MONGODB_URI`           | `mongodb+srv://user:pass@cluster.mongodb.net/app` |
| `JWT_SECRET`            | any 32+ char random string                        |
| `JWT_EXPIRE`            | `7d`                                              |
| `CLOUDINARY_CLOUD_NAME` | from Cloudinary dashboard                         |
| `CLOUDINARY_API_KEY`    | from Cloudinary dashboard                         |
| `CLOUDINARY_API_SECRET` | from Cloudinary dashboard                         |
| `CORS_ORIGIN`           | your frontend URL, e.g. `https://470-project-25ao.vercel.app` |
| `NODE_ENV`              | `production`                                      |

### Frontend (`memestack/frontend`)

| Key                       | Example                                   |
| ------------------------- | ----------------------------------------- |
| `REACT_APP_API_BASE_URL`  | `https://<backend-deployment>.vercel.app/api` |
| `REACT_APP_CLOUDINARY_CLOUD_NAME` | from Cloudinary dashboard         |

Copy `.env.example` in each folder to `.env` for local development.

## Local development

```bash
# 1. install deps
cd memestack/backend && npm install
cd ../frontend && npm install

# 2. run backend (port 5000)
cd ../backend
npm run dev

# 3. run frontend (port 3000)
cd ../frontend
npm start
```

The frontend proxies API calls to the backend via `REACT_APP_API_BASE_URL`.
For local dev, point it at `http://localhost:5000/api`.

## Deploying to Vercel

### First-time setup

1. **Create two Vercel projects** from the same GitHub repo:
   - `memestack-frontend` → root `memestack/frontend`, framework = CRA
   - `memestack-backend`  → root `memestack/backend`,  framework = Other
2. **Set env vars** on each project (see table above).
3. **Push to main** — both projects auto-build and deploy.
4. **Update `CORS_ORIGIN`** on the backend to the actual frontend URL once
   it's assigned.
5. **Update `REACT_APP_API_BASE_URL`** on the frontend to the actual
   backend URL, then redeploy the frontend so the new env var is baked in.

### Ongoing deploys

- Push to `main` → both projects redeploy.
- For hotfixes, `vercel --prod` from each project folder works too.
- CRA inlines env vars at build time, so frontend env changes require a
  rebuild (Vercel does this automatically on env-var save if you tick
  "redeploy").

## Post-deploy smoke test

1. Open the frontend URL.
2. Register a new account → should land on Dashboard.
3. Upload a meme → confirm image loads from Cloudinary (URL contains
   `res.cloudinary.com`).
4. Like / comment on a meme → refresh and confirm persisted.
5. Open **Analytics** → stat cards render with zeros for a new account.
6. Open **Templates** → seed templates visible (if seeded).
7. Log in as admin user → **Moderation** page loads; non-admin sees
   "Access denied".
8. Switch theme via **/theme-demo** → preference persists across reloads.

## Troubleshooting

- **CORS error on API calls** — `CORS_ORIGIN` on backend doesn't match the
  exact frontend origin (check protocol + trailing slash).
- **401 on every request** — frontend `REACT_APP_API_BASE_URL` points to the
  wrong backend, or the backend is redirecting `http → https` stripping the
  auth header. Use the canonical HTTPS URL.
- **Cloudinary upload fails** — env vars typo'd or account hit the free-tier
  throughput cap. Check Cloudinary dashboard usage.
- **"MongoDB timed out"** — Atlas IP allowlist missing Vercel's IPs. Set
  Atlas network access to `0.0.0.0/0` for serverless (acceptable because
  the cluster is still auth-gated).
- **Build fails on Vercel** — usually a missing peer dep. Rebuild locally
  with `npm ci` to catch it, then commit the fix.

## Rolling back

- Vercel → project → Deployments → find the last good deploy →
  **Promote to Production**.
- Roll back frontend and backend together if a breaking API contract change
  shipped.

## Admin seed

To promote a user to `admin`:

```js
// from backend, or via MongoDB shell
db.users.updateOne(
  { email: 'you@example.com' },
  { $set: { role: 'admin' } }
);
```

Then log out / log back in on the frontend so the JWT picks up the new role.
